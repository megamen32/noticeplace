[02] СИГНАЛ → ДЕЙСТВИЕ → ПРОВЕРКА

Заметить —
только начало.

Красная точка сообщает, что что-то не так.
Дальше нужен контекст: что случилось,
кто реагирует и помогло ли это.

  1. 01

    Поймать сигнал

    Ресурсы хоста, недоступный сервис, ошибка в логе или событие от твоего приложения.

    DETECT
  2. 02

    Собрать контекст

    Повтор одного сбоя дополняет инцидент, а не создаёт ещё один независимый поток уведомлений.

    CORRELATE
  3. 03

    Передать в работу

    Уведомить в Telegram. В настроенном агентском сценарии — предложить план и получить решение человека.

    ACT
  4. 04

    Проверить результат

    Слова агента «готово» недостаточно. Состояние подтверждает отдельная проверка исходного сигнала.

    VERIFY

Инструкция по развёртыванию
SHELL / CODEX
codex mcp add notify -- \
  npx -y github:megamen32/noticeplace
Команда добавляет MCP, а не разворачивает систему. Адрес центра и доступ настраиваются отдельно. Начни с инструмента noticeplace_instructions.
HTTP / КОНТРАКТ
POST /v1/events
Authorization: Bearer <project-token>
Idempotency-Key: <event-key>
Отдельный токен на проект, стабильный ключ события. Схема тела запроса и разрешения — в контракте источника ↗. Учётные данные каналов остаются в центре.
