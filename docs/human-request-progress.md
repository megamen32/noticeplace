# Ход глубокого разбора в исходной карточке

После выбора `deep_analysis` Telegram poller атомарно сохраняет решение и фазу
`accepted`, затем редактирует исходное сообщение: «Принял, запускаю глубокий
разбор…». Карточка сохраняет `telegram_chat_id` и `telegram_message_id`.
Внешний исполнитель получает сохранённый ответ после освобождения блокировки
редактирования. Повтор callback показывает текущую фазу, а не запускает новый
запрос и не возвращает кнопки выбора.

Исполнитель использует токен исходного проекта:

```http
POST /v1/human-requests/{request_id}/progress
Authorization: Bearer <project-token>
Content-Type: application/json

{"phase":"running","session_url":"https://agent.bezrabotnyi.com/#/session/codex%3Asession-id"}
```

Допустимы только поля `phase`, `session_url`, `message`. Фазы:
`accepted` → `running` → `completed` или `failed`; допускается переход прямо
из `accepted` в итоговую фазу. `message` — пояснение или результат по-русски,
до 1500 UTF-16 единиц. `session_url` — только HTTPS URL Agent Herder на
`agent.bezrabotnyi.com`, путь `/#/session/<session-key>`, до 1024 символов.
Другие хосты, логины, порты, query и произвольные пути запрещены. Ссылка
неизменяема после привязки; после завершения сохраняется кнопка «Открыть сессию».

API возвращает HTTP 200 и `ask_human.response.v1` с объектом `progress`.
Чужой project token возвращает 401, как остальные producer API. Запрос должен быть разрешён именно как
`deep_analysis` и уже иметь привязку к исходной Telegram-карточке. Повтор того
же обновления безопасен; задержанная более ранняя фаза возвращает и отображает
текущее состояние. Итоговая фаза и результат неизменяемы. Пример результата:

```json
{"phase":"completed","message":"Разбор готов. Предложил ответ и проверил исходные данные."}
```

Notice Place вызывает только `editMessageText`, никогда не отправляет отдельное
сообщение. Предел Telegram соблюдается в UTF-16, статус и URL сохраняются за
счёт сокращения тела. Данные сохраняются до попытки edit; при сетевой ошибке
исполнитель повторяет тот же POST. Ответ «message is not modified» считается
успешным повтором. Остальные ошибки и несовпавшая квитанция не маскируются;
последующая попытка снова редактирует тот же ID. Producer не получает права
выбирать chat, topic, message ID или Telegram credentials.
