2. MatrixRTC: QA A/B используют только собственные отдельные UUID и не получают owner/root/Bash privileges; owner Matrix address отображается только на UUID owner phone/Telegram. После audio/STT фикса провести ровно один последовательный QA Matrix-диалог: речь передаётся, транскрибируется и даёт содержательный русский ответ с per-user AI-маршрутом. Не запускать параллельный/дублирующий QA-звонок, owner call или cellular call. Пустой realtime/post-call transcript либо PCM/result из другой комнаты не засчитывается.
3. Секретарь: selector должен выбирать `SecretaryBrain`/`mode=secretary` для owner mapping и QA B; живую разговорную проверку проводить только на QA A/B Matrix-паре. Owner identity не использовать как тестовый собеседник. Selector readback сам по себе не закрывает live SDK/dialogue acceptance.
4. Эскалация: подтверждённый ответ в Matrix/Telegram должен останавливать цепочку. Проверку телефонного этапа после подтверждённых пропусков проводить без набора — через согласованный non-dialing test sink/receipt; реальный телефон/PSTN/GSM/SIP запрещены для тестов. `uncertain` не считать пропуском, UNKNOWN/accepted не повторять.
5. У каждого исправленного репозитория есть разрешённая опубликованная версия, проверяемая запись релиза и понятный способ вернуться к последней хорошей версии. Для shared/external репозиториев использовать `megamen32-dev`; upstream `main` не сливать автоматически.
6. Для повторяемых MatrixRTC проверок сохраняются ссылки/идентификаторы существующей fixture-пары и назначение теста, но не секретные значения. Новые Matrix-аккаунты и выпуск через BotFather не требуются.

## Ограничения

- Сохранить чужой WIP и активные ownership-записи; перед правкой пути проверить текущего владельца и свежесть исходников.
- Не повторять старые или неопределённые доставки. `answered=true` прекращает эскалацию; `uncertain` не считается пропуском.
- Автоматические QA voice canaries — только между существующими ботами Matrix A/B в изолированной комнате; это отдельно от прямого owner/phone call. Owner authorization с 09:15 покрывает одну прямую попытку; она была отклонена до набора из-за отсутствующего gateway. Не повторять автоматически и не делать серию: при материальной готовности gateway/recipient route допускается одна свежая осознанная попытка в рамках этой авторизации. UNKNOWN/accepted не replay; answered=false/actor=null без dialogue не повторять без материального изменения готовности/необходимости.
- Сначала опубликованный/разрешённый dev target и source-backed review; upstream `main` shared/external репозиториев не сливать автоматически. Секреты и номера не помещать в отчёты или архив.
