# Передача плана Notice Place

Задание этого прохода — исследование минимум 20 минут и новый полный план. Исследование выполнено; внедрение, очистка базы и production звонки не выполнялись. План: `deliverable=plan`, `decomposition=complete`. Будущие этапы остаются queued.

Страница: https://lhc.bezrabotnyi.com/noticeplace/plan-20261107-2048-40f5d6d0b06a4f37b1997fe2/

## Порядок и оценка

| Волна | Этапы | Видимый результат |
|---|---|---|
| Первое облегчение | S01, S02, S04; S13 и S15 параллельно на своих объектах | Повторные технические сообщения прекращаются; настройки работают; Smart Edge не создаёт флаппинг-карточки; Matrix и независимый watchdog восстанавливаются. |
| Рабочий интерфейс и исполнитель | S03, S05–S07 | Быстрая доска, понятный текст, одна подтверждённая сессия и правильное продолжение вопроса/ответа. |
| Полный lifecycle | S08–S09, S12 | SDK с достаточным контекстом и свежей проверкой; подробная история 7 дней, отсутствие replay после очистки. |
| Классификация | S10, K01, S11 | Gemma как ограниченный classifier; Kev сравнивается на том же корпусе и реальной машине. |
| Все источники | S16, M01–M13, S17 | Каждый enabled producer имеет versioned adapter, source verifier и installed proof; retired/QA не включаются автоматически. |
| Голос и итог | S14, F01–F02 | Проверенная допустимая эскалация, независимая приёмка, затем сутки машинного наблюдения. |

Исходная сумма: **34 этапа, 102 исполняемых листа, 1510 минут ≈25 часов активной работы**, включая оформление текущего плана. Это суммарный труд, не обещание закончить через 25 календарных часов. Часть работ параллельна; на первом проходе ориентир **2–4 рабочих дня плюс 24 часа наблюдения**, с пересчётом после S05/S16. Это плановая оценка, не измеренная скорость и не гарантированный deadline. Первое облегчение поставляется в начале, не после миграции всех consumers.

У ряда небольших существующих адаптеров оценена только известная часть. Число runtime экземпляров, точная причина ATV exit1 и возможность Telegram call proof ещё не известны. При новых объектах или более глубоком дефекте добавляются отдельные bounded листья; нельзя скрыть эту работу за одним 15-минутным пунктом.

## Решения, которые не надо переоткрывать

- Основной результат — отсутствие сообщений без необходимости действий человека, а не просто новая формулировка лога.
- Существующие Herder, SourceVerifier, queue/outbox и UserIO сохраняются. Новый orchestrator не нужен.
- Runtime incident repair: OpenCode / minimax-coding-plan, autopilot, без скрытого OmniRoute fallback. Gemma/Kev — только классификация.
- Проверка источника — исходящий pull с cursor/optional wait, webhook может ускорять, но не заменять durable API.
- Emergency не ждёт модель. Incomplete context не превращается в log. Только свежий source check закрывает.
- TTL 7 дней касается подробной истории; STOP, mute, компактное активное состояние и минимальные no-replay guard сохраняются.
- Все тестовые голосовые вызовы — только изолированные Matrix bot accounts/room, без реальных людей и телефонного fallback. Telegram live voice не маркировать проверенным без разрешённого независимого доказательства.

## Владение и приёмка

Один Lead интегрирует и принимает результат. Owner labels в листьях — плановые роли, не созданные агенты. В этом проходе исполнители не запускались. При выполнении выбрать реальные сессии и записать их, не выдавать роль за live executor.

Пересекающиеся изменения NoticePlace core/http идут последовательно по dependencies; adapters можно выполнять параллельно по разным путям. Registry имеет одного интегратора: consumer workers возвращают отдельные receipts, не правят общий JSON одновременно. Все установки — штатным release путём, main, с сохранением чужого WIP.

Каждый release фиксирует source SHA, artifact digest, installed hash и реальный consumer outcome отдельно. Предыдущий artifact/config остаётся для scoped rollback; receipt/STOP/rules не откатываются в состояние, допускающее повтор внешнего действия. Emergency и тишина не отключаются из-за неисправности classifier.

`research.md` содержит причины, evidence references, решение и точные сценарии приёмки. `research/` — безопасные измерения и скриншот. `plan.json`/`leaves` — канонический план; менять только через LhcPlan MCP, затем build/check --handoff. Прямую правку generated graph/html не делать.

Чужие `.gitignore`, `bin/notify-center`, untracked implementation и старые task trees остаются нетронутыми. Для публикации только этих документов использован detached Git worktree от remote main, без новой ветки. Продакшен не исправлен этим коммитом.
