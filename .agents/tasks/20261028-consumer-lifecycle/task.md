# Инциденты: один исполнитель и подтверждённое закрытие

Владелец уточнил 28.10.2026: отдельная сессия на каждый хост и тип проблемы. Повторные сигналы одного потребителя не должны создавать параллельных исполнителей. Агент завершает свою работу, источник подтверждает восстановление. Обычные уведомления не должны бесконечно занимать активную очередь. Применяется Last Human Commit по явному запросу владельца; новые ветки и worktree не разрешены.

## До и после

На момент создания плана были установлены читаемые native-названия и повторное использование незавершённой сессии. work_finished, продолжение после завершения попытки, source-check запросы, миграция потребителей, группы и история уведомлений тогда ещё требовали установки.

Теперь установленный контур доказал полный переход на одном изолированном инциденте: две настоящие попытки в одной native-сессии, между ними независимый degraded; явные окончания выключали автопилот, независимый healthy закрыл карточку. Подтверждение ведущего: [ROOT-ACCEPTANCE.md](ROOT-ACCEPTANCE.md), точные runtime receipts: [REPORT-L17.md](REPORT-L17.md). Независимые браузерные проверки подтвердили native continuation, раздельные группы, историю и разные состояния работы ИИ/источника. Последние статусы установки GPTAdmin и локализации панели отражены в листьях L27/L29.

## Решение

Рассмотрены три маршрута: обязательный callback каждого клиента; сохранение только периодического health.recovered; совместимый периодический recovery плюс pull-запрос актуальной проверки на существующем tick источника. Выбран третий: он сохраняет работающие интеграции и не позволяет агенту задавать URL или команду проверки. Идеальная схема имеет source-owned поколения и минимальные права каждого principal; минимальная рабочая реализация сохраняет это разделение без нового планировщика и без массового повторения старых доставок. [Кворум и независимая критика](../20261028-incident-lifecycle-council.md).

Общие поля: project, consumer_id (явный; иначе project+source_id), host_id, problem_type (явный; иначе signal_type). Correlation ID определяет эпизод и не входит в группу ремонта. Исходные source/signal сохраняются. Название карточки не является источником идентичности.

work_finished — явный идемпотентный endpoint исполнителя с attempt/session/harness. idle/error/stop не означают успешного завершения. Проверяющий получает полномочия из защищённого token scope verification_sources и principal_id, а не из body.actor. verification_due выдаёт request_id и generation; checker отдаёт healthy/degraded/unknown. Старые поколения не закрывают новый эпизод. HumanStop запрещает продолжение исполнителя, но не независимую проверку и закрытие по актуальному healthy.

TTL 24 часа относится к истории обычных уведомлений. Для health это просроченная проверка, а не resolved. Critical/emergency не исчезают молча. Исторический backlog не получает синтетический healthy и не replay-ится.

## Исполнение

Три независимые линии занимают три доступных worker-слота: L01 NoticePlace core (GPT‑6.1 Sol), L02 Herder (GPT‑6 Luna), L03 console (GPT‑6 Luna). Frontier выбран из проверенного живого Codex-каталога для межкомпонентных изменений состояния и SQL; квота 28.10 16:28 МСК: allowed=true, limit_reached=false, недельное использование 7%. Другие модели скрыто не подставляются. Инцидентный model route этим планом не меняется.

После L01 начинается L04 миграции потребителей; L05 объединяет все результаты и одно независимое ревью; L06 устанавливает опубликованный main, проводит изолированный QA и две свежие проверки реального интерфейса. Суммарное известное усилие: 115–225 минут. При трёх слотах критический путь max(L01→L04,L02,L03)→L05→L06: 80–160 минут. Полная оценка неизвестна до подтверждения количества самостоятельных устанавливаемых health-адаптеров. Предыдущие часы исследования не представлены как измеренное активное время; текущие source-отметки начала сохраняются в листьях.

## Поиск потребителей

GrepMesh использован для неизвестных расположений. Найдены canonical roots AutoFindClient, TelegramAuto, video_watching, universal-userio, universal-inbox, agent-harness-fleet, ServerAdministration automation/ops, gptadmin и Hermes. Первые широкие выдачи были обрезаны и содержали архивные/worktree копии; server-88 несколько раз timeout. Последующие canonical-prefix jobs server-100 закончены; service-crash-watch вернул partial из-за unreadable paths. Это не полный подтверждённый inventory флота. По обновлённым правилам обычный поиск внутри известных корней выполняется bounded rg; XERJ применяется для ranked retrieval при необходимости.

Маркер нового контракта: NOTICEPLACE_CONSUMER_V2. Он должен указывать на фактическую интеграцию и её способ проверки, а не служить одним документальным заявлением о миграции. Notification-only и QA клиенты классифицируются отдельно; им не включаются AI, телефонные маршруты или recovery автоматически.

## Контроль направления после расширения discovery

Первоначальный L04 выявил несколько самостоятельно устанавливаемых адаптеров; поэтому исходная оценка не стала обещанием полного срока. Опубликованы изменения infrastructure, AutoSell, video, ATV и разделение source/executor. Последняя проверка границ выявила три конкретных пропуска: live factory Herder не читает work_finished, отдельный зарегистрированный TGC watchdog ещё использует legacy resolve, external-site monitor обходит NoticePlace при сбое доставки. Они выделены L14–L16, три исполнителя работают параллельно. Следующий критический переход — закончить именно эти исходники, одно совместное ревью, установить фиксированные версии и провести один muted canary. Общие повторные аудиты и повторение старых операций не нужны.

## Приёмка и безопасность

Только свежая muted QA фикстура и разрешённые тестовые акторы. Принятые и UNKNOWN операции не повторяются. Ноль звонков и тестовых уведомлений владельцу. Чужой WIP и текущие сессии сохраняются. Секреты читаются по защищённым ссылкам без вывода значений. Commit/push только owned paths перед dependent deploy. Факты source/tests, deployed SHA и пользовательский результат фиксируются раздельно. Листья — источник статусов; graph/HTML/Markdown генерируются из них.
